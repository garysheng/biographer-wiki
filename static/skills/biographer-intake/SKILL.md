# biographer-intake

The personalized intake skill for **biographer.wiki** (https://biographer.wiki). Hosted at `static/skills/biographer-intake/SKILL.md`, served openly at `https://biographer.wiki/skills/biographer-intake/SKILL.md`, and discoverable via a thin local stub.

## The wiki

- **URL:** https://biographer.wiki
- **Purpose:** A reference wiki on collecting a person's life story with AI agents: transcripts, characters, moments, a growing timeline, and the forms a biography projects into.
- **Intake mode:** `authored-canon`. You grow this wiki by authoring original, coherent thinking in its voice, not by mapping external sources.

## The one law: coherence with the canon

Before authoring, scan the existing pages for prior framings of the idea. Enrich or sharpen what already exists before adding a new page. New thinking must cohere with the canon, not silently contradict it. Match the wiki's voice rules.

## Repo fast-path

Everything an agent needs to go straight to authoring, without re-deriving the repo.

- **Repo:** `~/Documents/github-repos/biographer-wiki` (GitHub: `garysheng/biographer-wiki`). Vercel auto-deploys on push to `main`.
- **Docs IA (top-level folders under `docs/`):**
  - `docs/concepts/` — the lexicon. One page per coined term, noun-phrase title, kebab-case filename matching the slug (`/concepts/<slug>`).
  - `docs/principles/` — the discipline. What holds true across every collection effort (`/principles/<slug>`).
  - `docs/ontology/` — the shapes: transcripts, characters, moments, the timeline, projections (`/ontology/<slug>`).
  - `docs/reference/` — tools, glossary, voice rules.
  - `docs/start-here/index.mdx` — the homepage (`slug: /`). Edit in place; never create a root `docs/index.mdx`.
- **Sidebar:** `concepts/`, `principles/`, and `ontology/` are autogenerated in `sidebars.ts`, so a new page in those folders needs NO sidebar edit. Only a brand-new top-level section touches `sidebars.ts`.
- **Page anatomy:** frontmatter (`title`, `slug`, `description`, and `image:` if the page has a hero), H1 matching the title, one italic definition line under the H1, `---` divider, named H2 sections, Further Reading. Every page's `description` doubles as its OG meta; the template renders per-page share cards at build time.
- **Voice rules:** `docs/reference/voice-rules.md` in this repo; canonical spec at https://garysheng.com/voice.md. No em dashes, no "not X, but Y" inversions, no filler.
- **Hero render (one working command):** `./illustrations/scripts/render-hero.sh <slug> "BEAT ONE: ... BEAT TWO: ... BEAT THREE: ..."` from the repo root. Register comes from `hero_register.register` in `wiki.config.json` (warm archival memoir). Output lands as WebP in `static/img/illustrations/`; embed the `.webp` path in the page body and set the same path as frontmatter `image:`. Note: `illustrations/refs/` has no blessed style references yet; render 2 to 4 and get them approved before batch-rendering heroes.
- **Ship:** `pnpm run build` (must pass; `onBrokenLinks: throw`), commit as Gary's default git identity (never add Claude co-author lines), `git push` (deploys). Then notify via the `update-gary-on-imessage` skill with the live URL.

## How to intake

1. **Scan** `docs/` for prior framings of the idea. Decide: enrich an existing page, or author a new one.
2. **Author** the page against the wiki's page anatomy (frontmatter, H1, one italic definition line, named H2 sections, Further Reading). Write in the wiki's voice; read its voice-rules page first.
3. **Cross-link** related concepts. Never re-explain a concept that has a canonical home; link it.
4. **Voice-check** the draft against the wiki's voice rules.
5. **Wire the sidebar** for any new page.
6. **Build** (`pnpm run build`, which enforces `onBrokenLinks: throw`) and fix every broken link.
7. **Commit and push** (Vercel auto-deploys).

## When NOT to use

- Faithfully mapping an external source (that is source-grounded mode).
